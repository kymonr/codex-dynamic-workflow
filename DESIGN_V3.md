# Codex Dynamic Workflow v3.0.0 — Runtime implementation contract

Date: 2026-09-06. User accepted defaults: Runtime is authority when selected; native and codex exec backends; one backend per run; read-only recovery initially; SQLite plus append-only events. No commit/push/merge. v2.0.2 remains the behavior baseline, not an unfinished phase.

## Scope and authority
Implement a small usable Python 3.11+ standard-library runtime in this project. Keep the current canonical invocation and explicit-only legacy alias. Preserve existing profiles, global configuration, the old codex-workflow repository, existing reports and user changes. Do not git init, install dependencies, alter ACLs, bypass approval/sandbox/hook trust, deploy, or create a daemon. The current source root is non-Git. One active writer only; this task uses RDC session PID 29280 (replaces terminated PID 19604), not other project sessions.
Native mode means a real external-host bridge: the runtime admits a node and exports a bounded task; the Codex host uses its actual native tools and reports the exact child ID and completion. Python must not pretend to implement spawn_agent or silently launch exec in native mode. Exec mode launches real codex exec through a literal argv, never shell-built prompt commands. Ordinary skill-only native use remains possible but must not claim runtime guarantees.

## Deliverables
Provide a documented CLI, importable runtime API, strict JSON task/result input, example read-only DAG, standalone deterministic tests, and a self-contained installed Skill entrypoint. Reuse the 2.0.2 budget decision code or share one authoritative implementation rather than silently creating divergent copies. Preserve existing ownership/adoption/rollback protections. Version source, installed Skill, package policy, alias and runtime consistently as 3.0.0.
The implementation must include persistent dynamic graph scheduling, atomic reservations, source identity and drift checking, permissions and cooperative writer exclusion, an evidence/claims store, bounded selective task context, interruption recovery, status/events/report commands, native bridge and exec adapters. No automatic backend switching, nested workflow, writer replay, background daemon or Web UI.

## Storage and graph
Use SQLite with foreign keys, busy timeout, explicit BEGIN IMMEDIATE transactions, schema-version checks, and durable commits. State changes, reservation accounting and the corresponding append-only event must commit together. Events have monotonic IDs; normal APIs never edit/delete prior events. Document that local database owners are trusted and this is not tamper-proof security.
A run records goal, backend, exact project root, permissions, route/contract identity, bounds, deadline, state and counters. A node records unique ID, role, task, exact source/read set, optional closed write set, risk/model/effort tier, required/optional status, checks, dependencies and attempt history. Validate types (bool is not int), identifiers, JSON duplicates and unknown fields. Reject cycles, nonexistent dependencies, self-dependencies, excessive depth/nodes, and duplicate IDs before mutation. Add bounded new nodes after returned evidence, with a reason; never rewrite executed history or reset cumulative counters by retry/rename.
Runtime is a trusted local controller, not an adversarial multi-tenant service. Only its controller API accepts graph expansion/authorization; child output is data and cannot authorize expansion, tier changes or writes. Dependency completion is not the same as acceptance. Failed/blocked requirements cannot produce a successful run; empty graphs and unexamined required scope are not success. Finishing/closing a run is explicit so useful late expansion is not silently discarded.

## Reservations, attempts and lifecycle
Admission and attempt creation use one transaction. Counts include successful, failed and uncertain dispatches; no refund for failure or retry. Required not-started nodes reserve both total approved and applicable strong allowance; optional work cannot consume that reservation. Economy reserve is cumulative per run, preauthorized, and inside absolute bounds. No expensive unapproved expansion. Record token usage when valid, otherwise UNKNOWN; do not interpret missing usage as zero or claim a hard monetary cap.
Separate total launches, active capacity and retained native-thread capacity. A native completed-but-unreleased thread occupies host capacity until explicit host confirmation of release. Root/host must not release a writer just because wait timed out. Use per-attempt fencing tokens; duplicate identical completion is idempotent, conflicting or stale completion is rejected. Binding external IDs and execution-start intent must be recorded; the crash gap between dispatch intent and returned child ID is UNKNOWN, not permission to replay.
Cancellation stops new admission immediately, marks queued work appropriately, and requests stop of active work without fabricating termination. Expiry alone does not mean a process/thread stopped. Recovery can requeue only read-only attempts after explicit terminal/no-active confirmation and revalidation of source and contract; retain old attempts and consumed allowances. Never automatically replay a write node. Failed or drifted checks remain visible and cannot be relabeled PASS to finish.

## Evidence and write safety
Bind each node to an explicit project-relative list of source files and their actual bytes/fingerprints, including relevant untracked inputs. Read pointers are navigation; derived claims never replace original sources. Reject traversal, absolute child paths, alternate data streams, symlinks/reparse points and source paths escaping the declared root. Do not scan the whole machine, read auth files or create copies of secrets. Reject or explicitly constrain empty source sets. Source fingerprints are consistency checks, not immutable snapshots or OS locks.
Recheck source identity at admission and acceptance. A changed source invalidates affected completed evidence and dependent acceptance, including after reopening/recovery; never silently overwrite its fingerprint to accept stale results. Claim records link node/attempt/source identity, exact evidence references, existence/applicability/impact and disposition. Untrusted child findings are proposals; controller dispositions are explicit and versioned. High-risk acceptance requires a capable non-author raw-source verifier whose relevant check passed on the same candidate; having an agent named reviewer is not proof.
Default run permission is read-only. A writer requires explicit implement authorization and a closed owned file set. No commit/push/merge command is implemented by this runtime. Serialize all writes and conflicting reads of mutable sources; locks are cooperative and must cover all runs sharing the runtime DB and physical source root. Include normalized aliases and prefix conflicts. Distinct DBs or tools outside the runtime are outside this lock boundary and must be documented, not called safe. Failed/interrupted writer ownership remains until effects and termination are explicitly reconciled. Never rollback/reset actual user source to clean a failed node.
Writer execution is opt-in: native bridge may export only an authorized write task and must bind post-write candidate plus a subsequent non-author review; exec adapter may initially reject writes if exact effect validation is not implemented. That limitation must be explicit, not disguised as a completed writing backend. Read-only recovery is the release scope; write replay remains manual. Scope permission, native sandbox and actual file effects are separate evidence.

## Executors and CLI
Exec adapter: literal argv, stdin task text, explicit model/effort from approved route, --json, --sandbox read-only for read tasks, current-client support check. Do not pass arbitrary config/flags from child data. Preserve existing saved authentication without reading/copying it. On Windows resolve the actual launcher/native executable safely; avoid shell injection. Require return code zero AND a real successful terminal event AND valid nonempty structured result; turn.failed/error/truncated/malformed output must not become success. Handle multiple agent messages without trusting intermediate chatter. Completion usage is observational and unknown usage stays unknown. Do not persist reasoning events or arbitrary tool output into the shared claim store.
Timeout/cancellation: retain exact task-owned process identity; stop only that process tree when verified, never by executable name or untrusted PID. Confirm termination, otherwise mark unknown and retain capacity. A synchronous finite runner is sufficient; no daemon. Do not leave unmanaged descendants when the foreground process exits. Runtime API admits ready independent nodes up to bounded capacity; a serial exec runner is acceptable if documented, but the concurrency-safe queue must work across competing callers.
Native adapter: explicit acquire/start/bind/result/release protocol; session tools remain owned by Codex host. Expose the full task contract including exact cwd, raw sources, permissions, model intent, checks, cancellation state and attempt identity. Reject results from the wrong backend, attempt, node or snapshot. Native result/termination receipts are trusted-host attestations, not OS-attested proof. Include exact invocation instructions in Skill reference docs and demonstrate a real native child when available.
CLI should support init/create run, add nodes from a plan JSON, next/dispatch, bind native child, complete result, release/confirm termination, retry/recover read-only, cancel, status, events and final report/close. Commands must be usable from this project and via the installed Skill; source-path assumptions cannot silently break installation. Read-only status/inspection must not create a missing DB or mutate events. Clean failures should return nonzero with structured diagnostics.

## Validation and release gates
Keep all 93 v2 regressions. Add runtime tests for transactional atomicity, concurrent admission, required strong/total reserves, duplicates and stale fencing tokens, cycle/depth/node bounds, scope escape/reparse behavior, same-file writer exclusion including competing runs, high-risk non-author verification, failure propagation, source drift before dispatch/acceptance/resume, cancellation, expired/unknown leases, explicit termination before readonly retry, no writer replay, completed native threads retaining capacity, backend immutability, and unknown usage.
Test exec adapter with an injected deterministic transport for valid JSONL, failed turn, nonzero exit, missing terminal event, malformed result, argument handling and timeout. Mark these as adapter tests, not model tests. Include deterministic CLI end-to-end tests and a restart/reopen exercise using real SQLite files. Unit tests must never launch paid models by default.
After implementation, Root independently reads source and runs tests. Then use a separate bounded read-only Codex reviewer, not the writer's own approval; repair confirmed issues and rerun affected/full tests. Perform a small real readonly exec smoke and a native bridge smoke if host supports it, bounded by at most 4 live test/review primary sessions plus at most 2 native children before requesting additional budget. Use actual current tool schemas. No changing security/configuration to make a smoke pass.
Only install after review and tests pass, through the existing ownership-protected installer, preserving exact recovery information. Runtime install must be self-contained and consistent. Confirm fresh discovery, final manifest and installation ledger, and report what is tested, unsupported and UNKNOWN separately. Preserve v2 history; append v3 milestones rather than rewriting previous evidence. Leave commits, pushes and merges to the user.
