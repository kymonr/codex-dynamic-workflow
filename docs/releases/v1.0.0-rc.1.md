本文件定义发布候选，而不是宣告已经发布。候选必须经过本地迁移、隔离安装、对 Dynamic Workflow 自身精确 RC Head 的只读自审，以及适用时的受限 Writer 候选人工审阅；只有全部门禁闭合后，才允许创建 `v1.0.0-rc.1` tag/GitHub prerelease。稳定版 `v1.0.0` 另需观察期后的独立决定。任何外部业务仓库 dogfooding 都是独立、可选的后续验证，不是本 RC 的发布依赖、合并门或 tag 门。

## 候选能力

- Workflow IR v3 与可信 `agent / map / verify / reduce / conditional / human_gate / bounded loop` runtime。
- checkpoint、events、CAS artifact、显式 gate decision、resume/no-replay 和 whole-workflow deadline。
- `design-swarm`、`ultra-review`、`repo-sweep` 固定预设。
- Auto Planner v1 固定注册表选择。
- Ultra Review 恰好七个 assignment 的 provider/local cardinality 合同，保持 `review-findings.item_limit=7`、投影 `23 / 24` 和 `max_concurrency=8`。
- Provider envelope、持久化 child output、map manifest、verifier linkage 和 bounded-loop recovery 的 fail-closed 校验。
- Worktree Writer v1 隔离候选流程：package → detached worktree → Luna Writer → effect reconciliation → fixed validation → frozen candidate → fresh Sol review → status/export。
- Windows 与 Ubuntu CI，以及多个真实 Windows RC 证据。

## 不包含的能力

- 模型生成任意可执行 DAG。
- 自动把 Writer candidate 应用到 canonical checkout。
- 自动 `git add`、commit、push、merge、release 或 deploy。
- Writer 隐藏 retry、模型升级、nested agent 或 reviewer 驱动的自动修复循环。
- 对 `observed_sandbox` 的独立宿主 attestation；该字段仍可能为 `unknown`。
- 把任一外部项目自动纳入 Dynamic Workflow 的发布门或 Writer authority。

### G2 — 旧本地工作区审计

目标：`D:\codex\projects\codex-dynamic-workflow`

### G5 — Dynamic Workflow 精确 RC Head 只读自审

目标只能是 PR #27 的精确当前 Head；在开始前重新核对 commit、tree、PR 状态和 clean checkout，不得把文档中的历史快照直接当作当前事实。

- [ ] 从精确 RC Head 创建 tracked-only、UTF-8、text-only、无 `.git`、无凭据/会话/数据库/浏览器配置的 sanitized export。
- [ ] 使用 `ultra-review` 直接审查 Dynamic Workflow 自身；scope discovery 必须恰好生成七个 assignment，`review-findings.item_limit=7`，projected total=`23 / 24`，`max_concurrency=8`。
- [ ] 所有 agent 保持 read-only；只允许一次真实 workflow，不允许自动 retry、第二个 preset、模型升级或权限扩大。
- [ ] 运行到 `review-gate=waiting` 后停止；不执行 `gate-decide`、`resume-ir` 或 Writer。
- [ ] 审阅真实 prompt dataflow、map/verify linkage、provider/local Schema、child recovery、manifest identity、artifact path/size/SHA/task identity、checkpoint/summary/resolved digest、events、agent claims、attempt/retry/upgrade 和 no-replay。
- [ ] 自审前后 sanitized target 的 path/size/SHA/mtime 指纹完全一致，无 `.pyc`、`__pycache__`、临时文件或 `CANCEL`。
- [ ] 给出基于 verifier 结果的 gate 建议，但建议不是 gate decision。
- [ ] 若发现 blocker 或 important finding，先通过独立修复提交和新的精确 Head 复验；不得用旧 run 替代新 Head 证据。

### G6 — 条件式最小 Writer candidate

G6 不是强制制造改动的测试门。只有 G5 产生一个同时满足以下条件的问题才进入 Writer：

```text
verifier-supported
low-risk
1–2 个 owned targets
不依赖真实账号、网络或外部业务系统
有精确的离线验证命令
```

- [ ] 没有合适 finding 时，记录 `WRITER_CANDIDATE_NOT_JUSTIFIED`，G6 以不适用正常关闭，不阻塞本 RC。
- [ ] 有合适 finding 时，package 绑定 Dynamic Workflow 精确 RC Head/tree、closed Schema、canonical digest、1–2 个 owned targets 和 fixed argv verification。
- [ ] `writer-plan` 必须零模型、零写入，不创建 run 或 worktree。
- [ ] `writer-run` 只执行一次；一个 Luna Writer、一个 fresh read-only Sol reviewer。
- [ ] 无 retry、upgrade、nested agent、network、Git mutation、外部 writable root 或 canonical apply。
- [ ] 实际 effects 必须严格等于授权的 create/modify 集合；delete、rename、mode、binary、symlink/reparse、submodule、Git metadata 或 unowned effect 均 fail closed。
- [ ] 两次 `writer-status` 与一次 `writer-export` fingerprint 一致；candidate、patch、文件、verification 和 reviewer record 相互绑定。
- [ ] 默认保留 worktree、lock 和 evidence，不 cleanup。

### G7 — 人工候选处置门

本门只在 G6 实际生成 candidate 时适用；否则记录 `NOT_APPLICABLE`。

- [ ] 用户查看 candidate patch、候选文件、验证结果、reviewer findings、limitations 和 `UNKNOWN`。
- [ ] 用户明确选择 `apply`、`fix-first`、`rethink` 或 `discard`。
- [ ] 未收到明确 `apply` 决定前，不修改 Dynamic Workflow canonical checkout。
- [ ] `apply` 必须采用新的、独立、可审计任务；不由 Writer runtime 自动继续。
- [ ] candidate 处置不得自动产生 commit、push、merge、tag、release 或 deploy。

### G8 — RC tag 与 prerelease

- [ ] 不自动更新日常 Skill；隔离安装继续保留。

### G9 — 稳定版观察

- [ ] 记录 RC 期间运行次数、workflow/preset、terminal state、agent claims、失败/阻断、retry/upgrade、artifact 完整性和人工 gate 决定。
- [ ] 没有未解释的 target mutation、重复执行、权限扩张、checkpoint/digest mismatch 或 Writer 越权。

- [ ] 观察期通过后，单独决定 `v1.0.0`；不因 RC 发布自动升级为稳定版。

## 可选外部 dogfooding

订单采集器或其他业务仓库可以在本 RC 之外使用 Dynamic Workflow 做独立验证，但必须满足：

- 使用另一个项目的明确授权、精确 Head/tree、敏感数据门和 model-visible export；
- 使用独立 run、gate、Writer package、人工 apply 和发布流程；
- 其失败、未认证、CI 状态或业务数据不得改变 Dynamic Workflow 本 RC 的 G1–G9 结论；
- 不得把外部项目写入本发布候选的必需门、合并条件或 tag 条件。
