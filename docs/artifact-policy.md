# Artifact Policy

适用范围：Team Router 仓库内的本地生成产物和证据文件。

## 默认分类

- `/pet-runs/`：本地图片或动效生成运行目录。默认不进 Git。除非后续任务明确把某个资产提升为已审查的项目资产，否则不提交生成帧、预览图、spritesheet、prompt、QA 截图或中间 manifest。
- `/ig_*.png`：仓库根目录下的本地生成图片。默认不进 Git。现有文件按本地/用户所有产物处理；删除、移动、归档或提升为项目资产前必须得到明确确认。
- `docs/evidence/`：可版本化的小型文本证据目录，用于记录审查、验证或项目决策依据。此目录故意不忽略。优先放 Markdown、JSON、TXT 摘要；不要存放大型或二进制生成资产。

## 留存规则

- 生成产物在归属确认前保留原位。
- 无关 closeout 不得删除、移动、覆盖或规范化生成产物。
- 已验收的证据文档不要从 `git status` 中隐藏；如果任务接受它们，必须显式 stage，因为 `git diff --name-only` 不会报告 untracked files。
- 证据条目应保持聚焦：包含日期、范围、来源命令或观察、结论和剩余风险。

## 归档规则

- 归档生成产物是独立动作，不等于忽略它们。
- 将产物移动到仓库外路径，例如 `D:\data\...`，需要明确用户授权，因为这会改变外部 workspace 状态。
- 如果某个产物被提升为项目资产，补充一个小型 manifest 或 evidence note，说明来源、owner、用途和验证结果。

## 当前策略结果

- `pet-runs/` 和根目录 `ig_*.png` 被视为 ignored local artifacts。
- `docs/evidence/` 保留为小型审查/验证证据目录。
- 本策略不删除、不移动、也不提交现有生成文件。
