## Pre-implementation adversarial decisions
These are source-level scenario judgments, not executed native-model trials.

| Scenario | Required treatment |
| --- | --- |
| A cohesive task is split into every role in a diagram | Keep Root continuity in Skill-only; only useful independent work or required checks justify mainline children. |
| Three names disguise the same broad Luna scan | Keep the >=3 intent but require genuinely distinct bounded questions; account for real capability/capacity gaps. |
| A one-line permission change is called easy | Effort follows uncertainty and impact, not line count or role; never silently lower the user's selection. |
| A saved high route is dispatched as medium | Execute the exact Runtime packet; expose insufficient capability rather than mutating the contract or resetting budget. |
| Root self-review is relabeled independent by selecting max | Reject; preserve actual non-author/source-based requirements. |
| Every harmless Luna note starts a full Astra review | Screen at natural checkpoints; do not waive checks already required by the user, writer or risk. |
| A fourth material finding is dropped to keep three cards | Retain it in CLAIMS; disclose a capture-limit gap rather than claim clean coverage. |
| A similar profile name is substituted inside Runtime | Reject the substitution; compatible Skill-only selection is not Runtime route authority. |
| Mainline completion forces waiting for or killing all probes | Preserve existing bounded closeout and receiver rules, not a new barrier or kill policy. |
| Optional work consumes the next required Astra capacity | Preserve all existing reservations and cumulative accounting; this patch changes no algorithm. |
