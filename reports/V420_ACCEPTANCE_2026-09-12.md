## 对抗性审核与修复

审核重新检查完整 diff、预算纯函数调用、create/acquire/resolve/finish、安装清单及文档，不把首版设计视为正确。

| 问题或攻击面 | 处理与反例 |
| --- | --- |
| 只替换 writer 模型仍会侵占 Astra strong 额度 | 新合同精确区分 Sol 实施计账；两次总额度、一次 strong 可完成 Sol+验收；旧合同仍计两次 strong |
| Sol 被提升为修复目标后可能借 strong 标签自行关闭问题 | 拒绝 Sol 的 passing resolution；fixed 必须有当前候选的独立 Astra writer verifier |
| 保留的 Astra writer 不再属于默认路由，校验可能漏掉其 model 漂移 | 专项实际发现该缺口，补独立固定 profile 身份校验并保留失败日志 |
| 同时改 strong 路由与 profile 可能将必要验收替换为 Sol | 独立预期 model/profile 映射校验；变异测试拒绝替换必要 Astra 路线 |
| 额度、执行与写入边界被混淆 | 无验收额度时开工前拒绝；事件写入失败原子回滚；失败不退款；未释放 writer 仍锁写；只读回执不能释放 writer |
| 修改后沿用旧审查或只审改动文件 | 候选变更必须 refresh；相同 host 作者不能换模型标签自审；审查必须覆盖 writer 的全部绑定来源 |
