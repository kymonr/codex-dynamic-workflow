## Actual sequence and failures retained

1. Astra read the real source and returned a compact handoff. It stopped before
   Sol became the sole implementation controller.
2. Sol directly added failing regression tests and implemented version separation.
   Luna inspected immutable baseline source and identified an additional missing
   current-Runtime-in-supported-contracts check. Sol reproduced and fixed it.
3. A fresh non-author Astra context independently rejected the first candidate:
   lowering `runtime.version` could still suppress backend/route validation. It
   reproduced the false-green cases with in-memory source mutations.
4. The host returned the rejection to the SAME Sol execution Root, without
   creating a new writer, resetting the task allowance or letting Astra repair
   its own review target. Sol added the negative cases, fixed the validator's
   Runtime 4.2 baseline, added installation override protection and ran regression
   checks. Final independent acceptance and exact-head CI are recorded on the
   release PR/release rather than inferred from this document.

The run was not error-free. An unrelated automatic-preflight detour was stopped
before candidate writes; no denied Codegraph command was retried through another
route. A late first Luna spawn receipt was missed during interruption recovery,
causing a duplicate second launch. The duplicate was closed and subsequently
observed as interrupted/notLoaded. Both launches remain charged/recorded; the
incident is not rewritten as a single successful call. The retained first probe
completed, and no further child was dispatched during repair.

The Skill now explicitly carries completed preparation forward, forbids
automatically matched Skills from widening scope, and requires reconciling
previous attempts/child IDs before resumed writing or dispatch. Parent-turn
interruption is not child termination. These new guards have regression coverage;
they do not introduce a transactional Skill-only ledger or guarantee that a
future model can never repeat an error.

## Installation and validation boundary

`local_overrides` is an optional exact path-to-SHA256 map in installation state.
It must be a subset of owned package paths and agree with their ownership hashes.
Replacing an override requires exact adoption; unchanged overrides survive an
installation state update, and rollback restores the previous state.
The deployment procedure preserves existing local Fast/Grok adaptations and
records them as overrides, not as a supposedly pure upstream installation.

Relevant checks include package validation, the complete source manifest,
version downgrade/malformed-declaration mutations, override/rollback regressions,
threaded-handoff contracts, full unittest discovery and both required CI jobs.
Live model execution, deterministic tests, local overlay readback and physical
resource release are separate claims.

Grok was not launched because this task had no additional independent question
requiring it. No comparative quality, latency, credit savings or Desktop hot-reload
claim is made. Runtime remains 4.2.0; the Skill release is 4.3.0.
